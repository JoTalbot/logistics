# Agent Log — Telegram Load Ingestion V1 — 2026-09-10

## Scope
Hardened the first production-shaped stage of Telegram load discovery: configured source collection, deterministic parsing, PostgreSQL persistence/checkpoints, canonical validation, canonical load persistence, transactional outbox and operational observability.

## Research
- GitHub Actions PostgreSQL service-container guidance.
- PostgreSQL official image initialization behavior.
- Existing project architecture, roadmap, domain/event contracts and Telegram skill.
- OpenTelemetry Python documentation for optional traces/metrics and OTLP export.
- Existing Telegram implementation and recent commits checked before modification.

## Implemented in this batch
- Canonical `loads` linkage to the source Telegram message with a unique provenance key.
- Accepted Telegram ads now persist canonical `loads` plus two ordered `load_stops` in the same transaction as source and parsed records.
- `LOAD_FOUND` and `LOAD_UPDATED` outbox events are emitted transactionally with canonical state.
- Outbox event idempotency keys prevent duplicate events during replay/reprocessing while allowing distinct content revisions.
- Duplicate source messages do not create duplicate canonical loads, stops or events.
- Replayed changed ads update the existing canonical load rather than creating a second load.
- Rejected/low-confidence ads remain in source/parsed storage without canonical load or outbox state.
- Deterministic replay fixtures and canonical-shape assertions added.
- Ingestion observer extended with duplicate/event information and optional OpenTelemetry traces/metrics via environment-controlled OTLP export.
- Optional `observability` dependency group added; core ingestion remains dependency-light when it is not enabled.
- Docker Compose fresh database initialization now includes migration 0003.
- PostgreSQL integration tests cover found, duplicate, update and rejected paths.

## Explicitly not implemented
- LLM parsing/enrichment of Telegram content.
- Automatic publication to DELLA/Lardi-Trans/Trans.eu/etc.
- Markup/pricing and automatic reposting.
- Autonomous negotiation.

## Verification
Repository writes were confirmed remotely. The CI workflow is configured to execute all three SQL migrations and pytest on PostgreSQL 17. Hosted CI must be checked after the push; local runtime execution is unavailable in the current environment.

## Compliance/security
`TG_API_ID`, `TG_API_HASH` and the Telethon session are runtime secrets. Telegram source access and retention must remain within applicable terms, permissions and law. Deterministic local parsing is retained for V1 rather than introducing an AI/ML processing path.
