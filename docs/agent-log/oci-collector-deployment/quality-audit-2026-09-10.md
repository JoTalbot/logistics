# Проверка качества Telegram-сборщика

**Дата:** 10 сентября 2026, 19:59 по Киеву (16:59 UTC).  
**Версия проекта:** `96d404a`.  
**Режим проверки:** только чтение, без изменения исходных данных и рабочего парсера.

## Вывод

Сохранение сообщений работает, но текущий парсер ещё не готов для надёжного автоматического подбора грузов и финансовых решений. Из **400 последних сохранённых сообщений** в выборке только **13 (3,25%)** прошли текущие правила формирования записи груза. Это **доля прохождения правил, не точность распознавания**.

На сервере выполнена проверка агрегатов и повторный локальный разбор. В отчёт не включены реальные тексты объявлений, телефоны и другие контактные данные. Для воспроизведения ошибок использованы искусственные примеры.

## Методика и ограничения

- По 100 сообщений с наибольшими Telegram message ID из каждого из четырёх источников; единый согласованный снимок PostgreSQL в read-only транзакции.
- На момент проверки в базе было 1 598 сообщений, включая ранее загруженную историю. Для таблиц ниже использована только выборка из 400.
- Проверены заполненность полей, прохождение правил валидации, повторы нормализованного текста, исключения при повторном разборе.
- Выполнены девять целевых искусственных сценариев. Они выбраны для проверки границ парсера и не являются репрезентативным тестом точности.
- Не выполнена ручная разметка реальных сообщений: нельзя достоверно определить precision/recall, отделить все пропуски парсера от отсутствующих в объявлении данных или подтвердить правильность 13 записей грузов.
- Это последние **сохранённые** сообщения; полнота относительно Telegram в момент аудита отдельно не проверялась.

## Почему сообщения не проходят правила

Причины пересекаются: у одного сообщения может не хватать нескольких полей.

| Причина | Сообщений |
|---|---:|
| Нет пункта отправления | 338 |
| Нет пункта назначения | 338 |
| Нет валюты | 337 |
| Нет положительной ставки | 332 |
| Нет типа груза | 212 |
| Оценка confidence ниже 0,6 | 210 |
| Нет положительного веса | 200 |

**Важно:** отсутствие поля в результате не доказывает отсутствие информации в исходном объявлении. Confidence вычисляется по найденным полям и не является калиброванной вероятностью правильности.

## Подтверждённые дефекты на искусственных примерах

| Входной формат | Ожидание | Фактическое поведение |
|---|---|---|
| `Київ → Львів` с явно указанными грузом, весом и ставкой | Маршрут, вес, ставка и валюта | Проверенные поля корректны |
| `Київ - Львів` | Два пункта маршрута | Оба пункта отсутствуют |
| `25 000 грн` | Ставка 25000 UAH | Ставка отсутствует |
| `22,5 т` | Вес 22500 кг | Корректно |
| `22000 кг` | Вес 22000 кг | Вес отсутствует |
| `22 t` с латинской буквой | Вес 22000 кг | Вес отсутствует |
| `кузов: тент`, `завантаження: 11.09.2026` | Тип кузова и дата | Оба поля отсутствуют |
| `500 доллар` | USD | **Ошибочно UAH** |
| `22 т зерно` на отдельной строке | Груз «зерно» | Тип груза отсутствует |

Итог: **2 из 9 сценариев прошли**, 7 показали дефекты или ещё не реализованные возможности. Это результат целевых тестов, не процент точности на реальных объявлениях.

## Повторы и сигналы для проверки

- Повторов ключа `(source, message_id)` для текущего tenant в базе: **0**.
- В выборке найдено **47 групп** совпадающего текста после приведения регистра и пробелов, **106 дополнительных копий** сверх первой в каждой группе.
- В **12 группах** одинаковый нормализованный текст встречается в разных источниках.
- Это повторы текста, а не доказанные дубликаты одного актуального груза: повторная публикация может содержать новый контекст. Автоматически удалять их нельзя.
- В **130 сообщениях** без распознанного маршрута есть сочетание слов через дефис/тире — кандидаты для проверки, не подтверждённые маршруты.
- В **8 сообщениях** есть ставка без валюты.
- В **11 сообщениях** распознан вес свыше 60 т. Нужна проверка: возможны как суммарный объём перевозки, так и ошибка извлечения. Это не основание автоматически отбрасывать запись.

## Рекомендуемый следующий этап

### 1. Сначала исправления с финансовым риском

- Исправить сопоставление валют; неизвестное обозначение не должно автоматически превращаться в UAH.
- Поддержать разделители тысяч, не принимая часть суммы за целую ставку.
- Сохранить запрет на автоматическое использование ставки без валюты.

### 2. Затем расширение распознавания

- Маршруты с дефисом/тире и явными метками отправления/назначения; не считать любое сочетание слов через дефис маршрутом.
- Единицы веса `кг`, `kg`, `т`, `t`, `тонн`; контроль нулевых и необычных значений.
- Тип груза после веса, тип кузова и дата погрузки с сохранением исходного представления и отдельной нормализацией.

### 3. Проверка результата до включения рекомендаций

- Добавить регрессионные тесты для всех найденных дефектов.
- Подготовить локальную контрольную выборку с ручной разметкой полей и классов «груз / свободная машина / другое». Не передавать исходные Telegram-тексты во внешние AI-сервисы.
- Сравнить старый и новый парсер на одной выборке без перезаписи боевых результатов, измерить точность и полноту отдельно по полям.
- Только после проверки повторно обработать сохранённые сообщения; идентификаторы и источники не менять.
- Группировать текстовые повторы для интерфейса, сохраняя каждую исходную публикацию и её происхождение.

**В рамках этого аудита исправления не применялись. Сборщик продолжает работать: первоначальные последние 100 сообщений, затем только новые.**
