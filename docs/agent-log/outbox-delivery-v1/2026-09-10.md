# Outbox Delivery V1 — 2026-09-10

## Task
Harden the publication/event outbox before adding real external provider transports.

## Research
- Inspected `AGENTS.md`, `STATUS.md`, `docs/ROADMAP.md`, current outbox implementation and PostgreSQL migrations.
- Confirmed existing `outbox_events.idempotency_key` uniqueness from migration 0003.
- PostgreSQL official documentation reviewed for `SELECT ... FOR UPDATE SKIP LOCKED` queue consumption and `INSERT ... ON CONFLICT` idempotency.
- `SKIP LOCKED` is appropriate for concurrent queue consumers because locked rows are skipped rather than blocking other consumers.

## Changes
- Added migration `0007_outbox_delivery.sql` with attempt count, availability time, lease timestamp/owner and last error metadata plus delivery indexes.
- Extended `backend/logistics/outbox.py` with bounded exponential retry delay, delivery leases, failure/retry handling and expired lease release.
- Kept the in-memory implementation deterministic for tests and shadow execution.
- Added `tests/test_outbox.py` covering retry backoff, idempotent append/publish, retry attempt increments and lease expiry.
- Updated `STATUS.md` with handoff and verification boundaries.

## Verification
Remote repository writes succeeded. Tests were not executed in the current GitHub connector environment, so hosted CI remains the source of truth.

## Decisions
- External publication remains disabled.
- Retry delay is bounded to one hour.
- Delivery leases are explicit rather than relying on process-local ownership.
- PostgreSQL claim/ack/failure worker is intentionally the next step so schema and pure delivery semantics land before database worker code.

## Lessons learned
Outbox idempotency and consumer concurrency need separate controls: a unique idempotency key prevents duplicate intent creation, while leases/`SKIP LOCKED` prevent concurrent workers from processing the same pending row simultaneously.
