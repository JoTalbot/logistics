# Обработка через серверный AIOS LLMBalancer

## Текущий маршрут

`collector → независимый enqueuer → пакет JSON → AIOS LLMBalancer (cloud_only + json_mode) → проверка ID/полей → отдельные нормализованные записи PostgreSQL`

- Endpoint: `http://127.0.0.1:9600/api/v1/aios/ask`.
- Реально используется работающий `octopus-aios.service`, сервер `/opt/octopus-aios-server.py` и `/opt/aios/llm/llm_balancer.py`; это не отдельный обходной клиент с копиями API-ключей.
- Версия нормализации: `logistics-extract-v3`. Алгоритм веса/денег V2 сохранён; имя версии больше не привязано к Qwen.
- Рабочий размер пакета остаётся 3, но может уменьшаться по лимиту входного текста.
- Очередь пополняется независимо от доступности балансировщика.

## Облачная обработка — явное изменение границ

Пользователь запросил отказ от локальной модели в пользу LLMBalancer. **Исходные тексты теперь передаются внешним провайдерам**, настроенным в AIOS. Прежняя гарантия «тексты не покидают сервер» больше не действует.

Ключи остаются в существующей конфигурации балансировщика `/etc/octopus/secrets.env`; они не копировались в репозиторий, контейнер сборщика или отчёты. Логи logistics не содержат тексты объявлений, ответы модели или API-ключи. Обучение моделей нашим кодом не запускается; политика хранения и использования данных внешним провайдером определяется его настройками и условиями. Права на обработку контента и условия источников по-прежнему должны соблюдаться.

## Исключение локального fallback

В существующий балансировщик добавлены обратно совместимые параметры:

- `cloud_only=false` по умолчанию — прежняя логика других клиентов;
- `json_mode=false` по умолчанию — прежний формат других клиентов.

Logistics отправляет оба параметра как `true`. Для такого запроса:

1. В пул допускаются только классы официальных облачных API (`OpenAICompatibleCloudProvider`, `GeminiProvider`, `HuggingFaceProvider`).
2. Ollama, браузерный RPA и локальные/фиктивные emergency-ответы исключены.
3. При недоступности облака возвращается `unavailable`, а не локальный текст-заглушка.
4. Кеш промптов AIOS для таких запросов отключён.
5. JSON mode включается там, где поддержан адаптером. Для облачного opt-in увеличен бюджет ответа до 4096 токенов и таймаут попытки провайдера до 20 секунд. Обычные вызовы других клиентов сохраняют прежние значения.

Перед запуском worker проверяет наличие `cloud_only` и `json_mode` в OpenAPI. Отсутствие опций приводит к отказу запуска, а не к неявному использованию старого API. Клиент дополнительно отвергает ответы с локальным/неразрешённым provider. Прямой старый вызов Ollama через `local_llm.extract()` отключён.

AIOS был перезапущен для применения патча. Изменения двух внешних файлов сохранены как `deploy/llmbalancer-cloud-only.patch`; резервные копии исходников находятся на сервере в `/root/logistics-balancer-backup/`. При обновлении AIOS эти возможности нужно сохранить/перенести; патч не отправлялся в отдельный репозиторий AIOS. Не откатывать API на старую версию без остановки/перенастройки logistics.

## Лимиты и надёжность

Существующий OpenAI-compatible адаптер балансировщика ограничивает пользовательский prompt 4000 символами. Logistics формирует полный JSON-пакет не длиннее **3800 символов**, включая ID и обрамление. Тексты не обрезаются. Одиночные сообщения, которые не помещаются, сохраняются с пометкой для проверки, а не передаются усечёнными.

- Один пакет — один запрос к API балансировщика. Внутри LLMBalancer возможны несколько попыток у разных облачных провайдеров.
- Схема результатов требует соответствия ID входным объявлениям; проверки и отдельные коммиты каждого результата сохранены.
- При невалидном JSON/отсутствующих ответах работают ограниченные повторы. Локальная модель не запускается.
- Первые облачные запросы выявили недостаток прежнего бюджета ответа (1200 токенов): были ошибки JSON. Добавлен opt-in JSON mode и бюджет 4096; 18 соответствующих задач возвращены на повторную обработку. В контрольном снимке после исправления у текущих задач не осталось error_type.
- Начальный переход перевёл 752 ожидающие задачи на облачный маршрут. Старые завершённые результаты сохранены, не выданы за новые облачные.

## Происхождение результатов

В `normalized` сохраняются:

- `llm_backend`: `aios-llmbalancer-cloud`;
- `llm_provider`: реально выбранный провайдер;
- `llm_route_fingerprint`: отпечаток политики маршрута.

Legacy-колонка `model_digest` для облачных задач содержит **отпечаток маршрута**, не хеш весов облачной модели. Физические веса внешних моделей не доступны для проверки. В истории сохраняются прежние локальные digest и результаты.

Все результаты по-прежнему `review_required=true`, `autopublish_allowed=false`. Быстрый облачный ответ не доказывает правильность маршрута, ставки или класса объявления.

## Память

Локальная `qwen2.5:1.5b` выгружена командой `ollama stop qwen2.5:1.5b`. Её вес на диске не удалялся. Перед выгрузкой процесс модели занимал около 1,8 GB; на контрольном снимке после переключения доступно около 4,2 GiB RAM.

Ollama как сервис не остановлена: `nomic-embed-text` другого приложения оставлена. Другие приложения могут иметь собственные настройки Ollama; запрет локального fallback применяется к запросам logistics, а не глобально ко всем клиентам сервера.

## Проверка

- **62 теста прошли**, 4 прежних интеграционных теста пропущены.
- На стороне AIOS отдельно проверены отказ cloud-only при наличии только локального провайдера и запрет слишком длинного prompt.
- Синтетический запрос прошёл через `groq-gpt-oss-20b` примерно за 0,5 секунды.
- Реальная обработка после исправления JSON-бюджета: сохранено 52 облачных результата на момент снимка; последние полные пакеты по 3 заняли 2,54 / 2,86 / 10,84 / 2,13 секунды.
- В БД наблюдались Groq GPT-OSS-20B, Groq GPT-OSS-120B, Groq Qwen и Gemini; конкретный маршрут динамический.
- На контрольном снимке `ollama ps` не показывал Qwen, только модель эмбеддингов. Это не benchmark точности и не гарантированная скорость всей оставшейся очереди.

```bash
cd /opt/logistics
docker compose -f deploy/compose.collector.yml logs --tail=20 normalizer
docker compose -f deploy/compose.collector.yml logs --tail=20 enqueuer
ollama ps
free -h
```
